# Contributing Guide

English | [Русский](./CONTRIBUTING.rus.md)

Thank you for your interest in contributing to the project.
We appreciate any help, whether it's code, documentation, feedback or promotion.

This document describes the contribution process in detail and is intended for those who really want to help the team.
Any type of contribution should not violate our [Code of Conduct](./CODE_OF_CONDUCT.md).

## Types of Contributions

There are several ways to contribute to the project:

- promotion,
- giving feedback,
- opening reports and issues,
- sending pull requests.

Any type of contribution is important to maintain the project.
Let's look at them in more detail.

### 1. Promotion

Help the project grow by sharing with others.

- Mention the project on social media or tech forums.
- Write blog posts or tutorials about how you use the project.
- Star the repository on GitHub or on another resources to show your support.
- Recommend the project to colleagues or friends who might find it useful.

### 2. Giving Feedback

Feedback helps us improve the project.

- Share your experience using the project.
- Suggest new features or enhancements.
- Report any pain points or usability issues.
- Participate in discussions in issues or community forums.

### 3. Opening Reports and Issues

If you encounter bugs or problems, please let us know by opening an issue.

- Check the existing issues to avoid duplicates.
- Use a clear and descriptive title.
- Provide steps to reproduce the issue, including code snippets or screenshots if applicable.
- Share environment details (e.g., OS, version of the project, dependencies).

### 4. Sending Pull Requests

If you'd like to contribute code or documentation, follow these steps:

#### Find what you want to implement or improve

#### Setting up the project

1. Fork the repository.
2. Clone the fork locally.
3. Follow build steps from readme.

#### Making changes

- Create a branch.
- Make changes.
- Write clear, concise commit messages.
- Add or update tests (if applicable and possible).
- Update documentation (if introduce new features or modify existing behavior).

See the project's [branching model](./doc/branching-model.md),
[coding style](./doc/coding-style.md) and [commit style](./doc/commit-style.md) conventions for details.

#### Submitting a pull request

1. Push changes to the fork.
2. Open a pull request.
3. Fill out pull request template.
4. Ensure all CI/CD and other checks (tests, linting, etc.) pass.
5. Wait for feedback and be ready to make adjustments if requested.

#### Code Review Process

- Maintainers will review pull requests and may suggest changes.
- Once approved pull request will be merged.

## F.A.Q

> Question: How do I know what to work on?
>
> Answer: Check the `Issues` tab for issues with `good first issue` or `help wanted` labels.

> Question: What if my PR is rejected?
>
> Answer: Don’t take it personally!
> The maintainers will provide feedback, and you can always discuss alternatives.

> Question: Can I contribute if I'm not a developer?
>
> Answer: Absolutely!
> Documentation, design, and community help are equally valuable.
